2. ¿Qué es el dashboard?
El dashboard es una aplicación interactiva (construida con Streamlit y respaldada por PostgreSQL) que
concentra la información inmobiliaria recopilada por el pipeline del proyecto y la convierte en
herramientas de trabajo diario: listados de propiedades, directorio de contactos estratégicos,
seguimiento de indicadores (KPIs), alertas de mercado, búsqueda asistida, analítica de comunidad y
tendencias.
2.1 Para qué sirve
 Decidir con datos: consultar oferta, precios y fuentes sin hojas de cálculo dispersas.
 Dar seguimiento comercial: guardar notas por propiedad y administrar la agenda de citas con
KPIs diarios.
 Detectar oportunidades: alertas de palabras clave como «Urgent Sale» y «Reduction Price» en
contenido autorizado.
 Preparar reportes: exportar la vista actual o un reporte ejecutivo completo en CSV, Excel, PDF,
JSON, PNG o SVG.
 Escuchar al mercado: analítica de preguntas, sentimiento y preocupaciones de la comunidad, y
tendencias emergentes.
2.2 Reglas de cumplimiento que debe conocer
El proyecto solo utiliza datos con acceso legal explícito, condición de socio, licencia de datos públicos o
exportaciones autorizadas y revisadas. El dashboard hereda estas reglas:
  No se extraen portales de consumo restringidos (por ejemplo Inmuebles24, Lamudi o Mercado Libre)
sin acceso de socio o API oficial.
 No se rastrean cuentas ni grupos privados, no se evita autenticación ni controles técnicos y se
respetan las reglas de robots y los límites de frecuencia.
 Las redes sociales (Facebook, X/Twitter, TikTok, YouTube) solo se incorporan mediante sus APIs
oficiales con la autorización requerida o exportaciones revisadas.
 La información oficial de programas de vivienda se almacena separada del contenido generado por
usuarios mediante los campos source_type y legal_status.
ADVERTENCIA: Si un proveedor le entrega un archivo que no proviene de una fuente autorizada, no lo
importe. Registre la situación con el responsable de cumplimiento antes de cualquier ingesta.

3. Arquitectura y flujo de la información
Antes de operar el dashboard conviene entender de dónde vienen los datos. El sistema es una cadena
de cinco pasos:
 Figura 1. Flujo de información: de las fuentes autorizadas al dashboard y sus exportaciones.
1. Fuentes autorizadas. El registro sources.json describe las fuentes de propiedades y
community_sources.json las comunidades y contenidos públicos, cada uno con su base legal,
método de acceso y política de rastreo.
2. Ingesta y normalización. ingest_sources.py lee los archivos colocados en data/raw, normaliza los
campos según property_schema.json y community_content_schema.json, deduplica registros y
escribe CSV en data/export.
3. Base de datos PostgreSQL. import_to_postgres.py carga los CSV en las tablas principales (ver
tabla siguiente).
4. Dashboard Streamlit. streamlit_app.py consulta PostgreSQL en vivo y presenta los 8 espacios de
trabajo con filtros, gráficos y formularios.
5. Exportaciones. Analítica y Tendencias generan archivos en data/exports y registran cada trabajo
en la tabla export_history.

4. Requisitos previos e instalación
4.1 Software necesario
 Python 3.10 o superior.
 Docker (para levantar PostgreSQL 16 localmente).
 Terminal: PowerShell en Windows; Bash en macOS o Linux.
4.2 Instalación paso a paso
1. Entorno virtual. Desde la raíz del proyecto cree y active el entorno:
python -m venv .venv
source .venv/bin/activate        # macOS / Linux
# .venv\Scripts\activate         # Windows
pip install -r requirements.txt
1. Base de datos. Inicie el contenedor de PostgreSQL y aplique el esquema:
docker run --name mexico-property-db \
  -e POSTGRES_USER=postgres -e POSTGRES_PASSWORD=postgres \
  -e POSTGRES_DB=property_data -p 5432:5432 -d postgres:16-alpine
docker cp db_schema.sql mexico-property-db:/tmp/db_schema.sql
docker exec mexico-property-db psql -U postgres -d property_data -f /tmp/db_schema.sql
4.3 Configuración del entorno (.env)
La aplicación y el dashboard leen la configuración de PostgreSQL de variables de entorno. Cree un
archivo .env en la raíz del proyecto:
POSTGRES_HOST=localhost
POSTGRES_PORT=5432
POSTGRES_DB=property_data
POSTGRES_USER=postgres
POSTGRES_PASSWORD=postgres

5. Ingreso al dashboard
 Figura 2. Puesta en marcha: primero el pipeline, después la aplicación Streamlit.
El ingreso tiene dos momentos: preparar los datos (una vez al día o cuando hay datos nuevos) y lanzar
la interfaz.
5.1 Procedimiento
1. Preparar datos y base de datos. Ejecute el script todo-en-uno desde la raíz del proyecto:
./run_pipeline.sh              # macOS / Linux
./run_pipeline.ps1             # Windows PowerShell
1. Lanzar el dashboard. Con el entorno virtual activo:
./.venv/bin/python -m streamlit run streamlit_app.py   # macOS / Linux
./.venv/Scripts/python.exe -m streamlit run streamlit_app.py   # Windows
1. Abrir el navegador. La terminal muestra la dirección; normalmente http://localhost:8501.
2. Cerrar la sesión de trabajo. Presione Ctrl+C en la terminal. PostgreSQL sigue disponible en
Docker para el próximo arranque.
CONSEJO: Si los datos ya están importados, puede saltar el paso 1 y ejecutar únicamente el comando de
Streamlit.
NOTA: La primera vez que entra, el dashboard crea sus tablas operativas (sección 3.1) y muestra datos de
demostración claramente etiquetados cuando aún no hay contenido comunitario importado (sección 9.2).

8.2 Nombres de archivo y destino
Los archivos se escriben en data/exports con nombres descriptivos que combinan el contenido, la zona
y el periodo, por ejemplo:
data/exports/real-estate-intelligence-metepec-last-30-days.pdf

NOTA: PNG y SVG exportan la gráfica de sentimiento real, no capturas de pantalla de la ventana. En
exportaciones grandes futuras se podrá interponer una cola de trabajos sin cambiar la forma de usar estos
botones; hoy las descargas son inmediatas.
Buenas prácticas:
 Registre en el nombre del comité o reunión el archivo PDF que usó; así podrá reconstruir qué datos
vio cada persona.
 Para series comparables, exporte siempre con el mismo periodo (por ejemplo «últimos 30 días»).
 El JSON conserva los metadatos de filtros: es la mejor fuente si alguien cuestiona un número
presentado.

3. Directorio vivo. Dé de alta un notario y un valuador con zona de cobertura; encuentre ambos
usando el filtro por perfil.
4. Semana de KPIs. Capture cinco días de registros (dos por encima de la meta 20+ y tres por
debajo) e interprete la gráfica de tendencia. Entregable: dos conclusiones escritas.
5. Alertas y oportunidad. Agregue la palabra clave «Precio reducido», ejecute el escaneo y derive
una coincidencia a una nota en Propiedades. Entregable: nota con el enlace de la coincidencia.
6. Reporte ejecutivo. Con filtros activos en Analítica, exporte el PDF, anexe también el CSV del
mismo conjunto y confirme ambos en export_history. Entregable: los dos archivos y la fila del
historial.
